基于ARM的Linux操作系统引导详解

卸载RCU回调函数

从前面介绍RCU过程中我们知道，在宽限期过后，RCU会产生中断，调用RCU回调函数，释放等待被释放的内存。这会对高性能计算造成影响。为了不影响高性能计算和实时操作，在采用全动态时钟节拍的系统中，有必要把本需要回调函数完成的任务委托给专门的内核线程（rcuo 线程），而把RCU回调函数从采用全动态时钟节拍的CPU卸载。rcu_init_nohz()函数的目的就是构建这样一种机制，确保 RCU 能够识别哪些 CPU 进入了“空闲/无节拍”状态，从而避免内核为了等待这些已经“睡着”的 CPU 报告状态而导致系统卡死（即 RCU 宽限期无法结束）。该函数定义在文件git/kernel/rcu/tree-plugin.h中，其定义为：

void __init rcu_init_nohz(void)
{
	int cpu;
	bool need_rcu_nocb_mask = false;
	struct rcu_data *rdp;
#if defined(CONFIG_NO_HZ_FULL)
	if (tick_nohz_full_running && cpumask_weight(tick_nohz_full_mask))
		need_rcu_nocb_mask = true;
#endif
	if (!cpumask_available(rcu_nocb_mask) && need_rcu_nocb_mask) {
		if (!zalloc_cpumask_var(&rcu_nocb_mask, GFP_KERNEL)) {
			pr_info("rcu_nocb_mask allocation failed, callback offloading disabled.\n");
			return;
		}
	}
	if (!cpumask_available(rcu_nocb_mask))
		return;
#if defined(CONFIG_NO_HZ_FULL)
	if (tick_nohz_full_running)
		cpumask_or(rcu_nocb_mask, rcu_nocb_mask, tick_nohz_full_mask);
#endif 
	if (!cpumask_subset(rcu_nocb_mask, cpu_possible_mask)) {
		pr_info("\tNote: kernel parameter 'rcu_nocbs=', 'nohz_full', or 'isolcpus=' 
    contains nonexistent CPUs.\n");
		cpumask_and(rcu_nocb_mask, cpu_possible_mask,  rcu_nocb_mask);
	}
	if (cpumask_empty(rcu_nocb_mask))
		pr_info("\tOffload RCU callbacks from CPUs: (none).\n");
	else
		pr_info("\tOffload RCU callbacks from CPUs: %*pbl.\n", cpumask_pr_args(rcu_nocb_mask));
	if (rcu_nocb_poll)
		pr_info("\tPoll for callbacks from no-CBs CPUs.\n");
	for_each_cpu(cpu, rcu_nocb_mask) {
		rdp = per_cpu_ptr(&rcu_data, cpu);
		if (rcu_segcblist_empty(&rdp->cblist))
			rcu_segcblist_init(&rdp->cblist);
		rcu_segcblist_offload(&rdp->cblist);
	}
	rcu_organize_nocb_kthreads();
}

函数的执行逻辑为：

该函数首先通过CPU掩码tick_nohz_full_mask和全局布尔变量tick_nohz_full_running，确定是否有CPU需要卸载RCU回调函数。tick_nohz_full_mask记录了哪些CPU被配置为全动态无节拍模式，tick_nohz_full_running用于指示系统当前是否处于 完全无时钟节拍模式运行状态。当用户在引导时通过内核参数 nohz_full=<cpu_list> 指定了部分 CPU核芯进入无时钟节拍状态，且内核配置了 CONFIG_NO_HZ_FULL 时，该变量会被设为 true。如果需要卸载RCU回调函数，则需要一个RCU 卸载位图变量（掩码），因此，需要将need_rcu_nocb_mask设置为true。

之后，该函数通过判断 RCU 卸载位图是否已经分配了内存，以及当前配置是否确实需要它，来确定是否为变量rcu_nocb_mask分配内存。rcu_nocb_mask为CPU 位图指针（RCU “隔离”位图），它的核心作用是标记哪些 CPU 进入了 无回调模式。

在为变量rcu_nocb_mask分配内存后，利用函数cpumask_or()初始化 RCU 的“隔离”位图。它会检查内核启动参数（tick_nohz_full_mask），并将这些 CPU 标记在 RCU 的内部掩码（指针rcu_nocb_mask指向的单元）中。这样，RCU 就知道哪些内核不需要频繁的时钟中断来辅助宽限期的推进。

在确定需要卸载RCU回调函数的CPU后，为了保证系统稳定，通过函数cpumask_and()从rcu_nocb_mask所标定的CPU中剔除不存在于cpu_possible_mask表明的CPU。

函数中使用的变量rcu_nocb_poll是一个 Linux 内核引导参数，专门用于优化配置了 nohz_full 或 rcu_nocbs 的系统。它的作用是改变 RCU 卸载（Offloading） 的工作模式。如果该变量为false（默认），当 CPU 将 RCU 回调任务卸载到后端的 rcuo 守护进程时，当产生了新的回调时，内核会发送一个 IPI来唤醒负责处理这些任务的“管家 CPU”。如果该变量为true，rcuo 守护进程会周期性地轮询是否有待处理的回调，而不是等待中断唤醒。

在利用pr_info()函数列印完CPU的RCU回调函数卸载信息后，函数通过for_each_cpu(cpu, rcu_nocb_mask)语句遍历由变量rcu_nocb_mask指定的需要卸载RCU回调函数的各个CPU，获取当前遍历到的 CPU 所对应的 rcu_data 结构体指针（rcu_data 存储了该 CPU 所有的 RCU 状态信息）。如果该 CPU 的分段回调列表（Segmented Callback List）尚未初始化，则进行初始化。for循环中最重要的操作是通过函数rcu_segcblist_offload将该 CPU 的回调列表标记为 SEGCBLIST_OFFLOADED 状态。

标记完成之后，通过函数rcu_organize_nocb_kthreads()为每一组 卸载的 CPU创建一个宽限期控制线程（Grace Period Control Kthread，通常命名为 rcuog/X），这个线程负责监控该组内所有 CPU 的宽限期状态。此外，还会为每个需要卸载的 CPU 创建一个独立的工作线程（Worker Kthread），这些线程专门负责执行该 CPU 产生的回调函数。函数rcu_organize_nocb_kthreads()会将 Worker 线程关联到其对应的宽限期控制线程上。这种层级结构（Leader-Follower 模式）是为了减少对宽限期检测逻辑的竞争，提高伸缩性。最后，它会将这些 rcuo 线程绑定到专门负责内务（ Housekeeping）的 CPU（非 nohz_full 的内核）上运行，这样可以确保那些运行关键任务的 nohz_full 内核不会被这些后台 RCU 线程抢占

一旦标记完成，该 CPU 产生的所有 RCU 回调将不再由该 CPU 自己的 RCU_SOFTIRQ（软中断）处理，而是交给专门的 rcuo 线程（通常运行在 Housekeeping CPU 上）来异步处理。

rcu_init_nohz() 的本质是告诉 RCU 系统，哪些 CPU 不用时钟节拍，并安排好谁来替这些 CPU 处理杂务，以防它们拖慢全局的垃圾回收进度。
